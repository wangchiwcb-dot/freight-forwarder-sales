## 一期交付边界

一期还原四个业务页面，补齐多人使用必需的登录、个人改密、员工与团队管理、权限、归档恢复、审计、数据备份及移动端体验。销售默认看本人数据，主管看团队，管理员管理公司范围；这是建议权限基线，原型未定义该规则。

电销指人工拨打后的记录，不包含电话线路、自动拨号、录音、AI、自动联系客户或消息群发。“发报价表”“客户下单”是跟进分类，不代表发送附件或创建运输订单。

首页走货图保留设计位置，但在真实销售票数来源未建立前显示“待接入”。这属于一期明确保留的功能缺口，不能宣传为已提供完整销售业绩分析。后续需定义销售票、客户/负责人关联、业务日期与取消规则，再接入真实统计。

## 实施顺序与完成条件

| 阶段            | 工作                                         | 完成条件                               |
| --------------- | -------------------------------------------- | -------------------------------------- |
| M0 契约冻结     | 核定业务规则、共享类型、字段与验收数据       | 前后端采用同一枚举、接口和统计口径     |
| M1 基础与身份   | 应用工程、样式、数据库迁移、登录、员工与团队 | 两名销售数据隔离，停用立即失效         |
| M2 客户闭环     | 列表、详情、建档、跟进、阶段变更、归档恢复   | 并发修改不丢数据，跟进和审计可追溯     |
| M3 接触闭环     | 电销/扫楼录入、历史筛选、转客户              | 取消不转化，重复提交不重复建档         |
| M4 工作台与验收 | 聚合、下钻、提醒、手机、错误状态、性能       | 统计与列表一致，四页桌面及手机均可用   |
| M5 阿里云预发布 | 独立数据库/服务、备份恢复、HTTPS、回滚演练   | 预发布验收通过，原有两个站点读验收通过 |
| M6 内部试点     | 个人账号、操作指引、2–5 人试用、反馈修正     | 试点完成主要闭环后再扩大到公司同事     |

本表是执行顺序，不承诺未经排期确认的交付日期。后续开发以阶段完成条件推进，不以静态页面可打开作为上线完成。

## 待核定事项与默认方案

这些事项不阻止继续编写或搭建应用；涉及正式业务范围与基础设施的选择，应在对应阶段落定并记入版本记录。

| 事项                 | 当前建议                                   | 需在何时确定                          |
| -------------------- | ------------------------------------------ | ------------------------------------- |
| 公司数据共享方式     | 销售本人、主管团队、管理员全公司           | M0；决定权限测试基线                  |
| 真实员工和团队       | 管理员逐人建账号；不开放注册               | M5/M6；名单不写入公共仓库             |
| 联系号码范围         | 沿原型：主电话为大陆手机，备用电话可为座机 | M0；如需海外/座机主号码须同步修订校验 |
| 客户阶段与回退       | 正向逐步确认；主管/管理员带原因回退        | M0                                    |
| 空号·停机的下次判断  | 暂沿原型默认可再访，可手动改为暂缓/拒绝    | M0；不解释为自动拨号计划              |
| 走货量来源           | 待接入；不以柜数或“下单”跟进次数替代       | 二期接入前                            |
| 域名、端口及资源     | 复用既有 ECS；独立子域名和应用服务         | M5 只读核查实际资源后确定             |
| 备份与恢复目标       | 采用后端文档的建议周期，实测恢复           | M5                                    |
| 内部推广渠道与负责人 | 先试点，提供使用指引与反馈入口             | M6；消息收件人、渠道、内容落实后发送  |
