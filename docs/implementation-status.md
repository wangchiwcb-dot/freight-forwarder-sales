## 业务实现与边界

- 客户和沟通活动分别建模；活动保存不自动建客户，取消转化不预标记成功。转化、客户创建/关联、活动链接、审计和幂等结果在同一事务完成。
- 客户归属与操作者权限在写入事务中重新校验；变更用版本号和行锁处理多人修改。员工调组/停用撤销会话，组织变更与最后管理员保护串行执行。
- 跟进和阶段事件保留历史；修改只发送本次字段，遗漏字段不覆盖旧值。提醒支持不变、清除、设置三个状态。归档不删除历史。
- 所有日期按上海时间呈现；筛选采用包含开始、不包含结束的区间。开户客户包含已走货客户。走货票数接口返回 `not_connected` 和 `null`，不会用跟进次数虚构票数。
- 登录使用哈希密码和 HttpOnly 会话 Cookie。生产 HTTPS、CSRF、来源验证、账号/IP 登录限流、受限数据库角色、脱敏日志均有实现。
- 手机主联系电话按设计基线限定大陆手机号。批量导入导出、录音、自动拨号、AI、真实票量接入和外部消息推送不在本次范围。

## 数据库

`database/001_crm.sql` 为 v1 迁移，包含公司、团队、员工、客户、跟进、阶段事件、沟通活动、审计、会话、幂等和迁移登记。业务关系采用公司ID与对象ID复合约束；手机号不设置唯一约束，改为权限范围内重复提示。

`database/roles.sql` 单独授权运行角色；历史表仅允许插入，客户使用归档。应用不会在启动时建表、迁移、创建员工或回退到演示数据库。维护清理和迁移连接与应用连接分离。详细字段与索引见 [数据库设计](design/database-design.md)。

首批仅开通一个团队的 16 人账号，1 位管理员、15 位销售。销售查看本人的客户和记录；管理员可管理试点团队。所有新账号首次登录必须改密；正式站验证不代替员工设置密码或录入业务。
